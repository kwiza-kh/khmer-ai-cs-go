# 三、P0 — 阻断级问题

## P0-1 · 侧边栏底部控件溢出，压在主内容上

**现象**：主题切换、语言切换、通知铃被挤出 224px 宽的侧边栏，语言图标和通知铃（含 12 角标）渲染到主内容区左下角，与主内容重叠。

**证据（DOM 实测）**：
```
aside          : x=0   w=224  right=224
footer         : clientWidth=223   scrollWidth=277   ← 溢出 54px
ThemeToggle    : x=12  w=199  right=211   (w-full 生效)
lang+bell 组    : x=211 w=64   right=275   ← 超出侧栏 51px
```
截图：`shots/light/inbox.desktop.png`（左下角铃铛+12）、`shots/zoom/sidebar-footer.light.png`

**根因**：`components/layout.tsx:243`
```tsx
<div className="flex items-center justify-between ...">
  <ThemeToggle />                                   {/* Button className="w-full ..." + shrink-0 */}
  <div className="flex items-center gap-1"><LanguageSwitcher /><NotificationBell /></div>
</div>
```
`ThemeToggle`（`components/theme-toggle.tsx:52`）写死了 `className="w-full justify-start gap-2 h-9 text-sm"`。Button 基类带 `shrink-0`，于是它吃掉整行宽度（199px），`justify-between` 失效，兄弟节点被推出容器；`aside` 又没有 `overflow-hidden`，所以直接画在外面。

**修复**：
```tsx
// theme-toggle.tsx — 让调用方决定宽度
export function ThemeToggle({ className }: { className?: string }) {
  ...
  <Button variant="ghost" size="sm"
    className={cn("justify-start gap-2 h-8 text-sm", className)} ...>
```
```tsx
// layout.tsx — 底部行改成 title 版图标按钮
<div className="flex items-center justify-between gap-2 border-t ... px-3 py-2">
  <ThemeToggle className="w-auto min-w-0 flex-1" />
```
并给 `aside` 加 `overflow-hidden` 兜底。

## P0-2 · Badge 文字被竖向裁切（全局，涉及表格/状态/平台/角色）

**现象**：所有 Badge 内的文字上下被切。放大后肉眼可见：`Google` 的 g 尾、`Password` 的 p 尾、`Telegram`、`platform_admin` 的下划线、`Active`/`Disabled`/`Default`/`API key required` 全部缺底。

**证据（DOM 实测）**：
```
inbox 行内 Badge:  height=16px  clientHeight=14  scrollHeight=17
                   padding 2px/2px  → 内容盒 10px
                   font-size 10px   line-height 15px   overflow:hidden
→ 需要 15px 行高，只有 10px 可用，切掉 5px
标准 Badge:        h-5(20) − 2(border) − 4(py-0.5) = 14px 内容盒 vs text-xs 行高 21px → 切 7px
```
截图：`shots/zoom/users-table.light.png`、`shots/zoom/badge-boxmodel.png`

**根因**：`components/ui/badge.tsx:8`
```
"group/badge inline-flex h-5 ... px-2 py-0.5 text-xs font-medium whitespace-nowrap overflow-hidden"
```
同时 `app/globals.css` 把字号令牌改写成了非标准值：
```css
--text-xs: 0.875rem;        /* 14px，shadcn 默认是 12px */
--text-xs--line-height: 1.5;  /* → 21px */
--text-sm: 0.9375rem;       /* 15px，默认 14px */
```
固定高 `h-5` + 固定 `py-0.5` + 21px 行高 = 必切。

**修复（二选一，建议都做）**：
1. `badge.tsx`：去掉与固定高冲突的行高 → 加 `leading-none`；或删掉 `h-5`/`py-0.5`，改 `py-0.5 leading-none` 由内容撑高。
2. `globals.css`：把 `--text-xs` 恢复为 `0.75rem`（12px）、`--text-sm` 恢复 `0.875rem`（14px），恢复标准阶梯。

## P0-3 · Tailwind v4 下裸 `border-*` 变成 currentColor，表格分隔线变近黑

**现象**：`/admin/users`、`/admin/tokens`、SLA 表格的行分隔线是**近黑色**粗线，与该页浅灰描边（`#d8dae4`）完全不协调；暗色下反过来变成近白线。

**证据（computed style 实测）**：
```
light: tbody tr border-bottom-color = rgb(16, 16, 20)   ← = --app-foreground
dark : tbody tr border-bottom-color = rgb(240, 241, 245) ← = --app-foreground
设计令牌 --color-border = #d8dae4 (light) / #1f222d (dark) —— 完全没被用上
```
截图：`shots/light/admin-tokens.desktop.png`、`shots/zoom/users-table.light.png`

**根因**：Tailwind v3 的 `border` 默认色是 gray-200；**v4 改成了 `currentColor`**。本项目的 `globals.css` 只定义了 `--color-border` 令牌，却缺少把令牌写回 `border-color` 的 base 层规则（全文只有 1 处 `border-color`，还是出现在 `transition-property` 里）。

**受影响面**：`components/ui/table.tsx`（TableRow/TableFooter/TableHead）、`card.tsx`（CardFooter）、`dialog.tsx`（DialogFooter）、`sheet.tsx`（四边）——都是裸 `border-b/t/r/l`。全项目 `border*` 工具类共 582 处。

**修复**：`app/globals.css` 增加
```css
@layer base {
  *, ::after, ::before {
    border-color: var(--color-border);
  }
}
```

## P0-4 · platform-admin「Messages (last 14 days)」柱状图永远不渲染

**现象**：图表区域只有底部日期轴（08-31…09-13），**没有任何柱子**。

**证据**：截图 `shots/light/platform-admin.desktop.png`；`shots/dark/platform-admin.desktop.png` 同样为空。

**根因**：`src/app/platform-admin/page.tsx:100`
```tsx
<div className="flex items-end gap-1.5 h-24">          {/* 容器 96px */}
  {data.daily_messages.slice(-14).map((d) => (
    <div className="flex-1 flex flex-col items-center gap-1">   {/* 高度 auto（items-end 不拉伸） */}
      <div className="w-full rounded-t bg-primary/70"
           style={{ height: `${height}%` }} />                   {/* 百分比对 auto 高度 → 解析为 0 */}
```
`align-items: flex-end` 让每列的高度由内容决定，柱子的 `height: 57%` 找不到可用的父高度 → 塌成 0。另外 `max` 在 `map` 内每轮重算（O(n²)），且日期标签用了 `text-[9px]`。

**修复**：
```tsx
<div className="flex items-end gap-1.5 h-24">
  {data.daily_messages.slice(-14).map((d) => (
    <div key={d.date} className="flex-1 h-full flex flex-col items-center justify-end gap-1">
      <div className="w-full rounded-t bg-primary/70" style={{ height: `${height}%` }} />
      <span className="text-[11px] ...">{d.date.slice(5)}</span>
    </div>
  ))}
```
（把 `max` 提到渲染前算一次）

## P0-5 · 登录页硬编码深色，不跟随主题；且首屏表单不可见

**(a) 主题不跟随**：`theme=light` 下登录页仍然是纯黑页。

**根因**：`src/app/login/page.tsx:163`
```tsx
<section className="fixed inset-0 overflow-y-auto bg-zinc-950 text-zinc-50">
```
整页使用 `zinc-*` 原生调色板（`border-zinc-800`、`bg-zinc-900/70`、`text-zinc-400`…），完全绕开了 `--color-*` 令牌体系；只有主按钮走 `Button` 默认（紫罗兰渐变）。结果是：一个浅色应用跳到一个硬编码黑页，品牌色只在按钮上出现一次。

截图：`shots/light/login.desktop.png`、`shots/zoom/login-4s.light.png`

**修复**：把 `zinc-*` 换成令牌（`bg-background` / `bg-card` / `border-border` / `text-muted-foreground`），或显式接受「登录页永远深色」并在文档里写死为设计决策（并去掉 `--color` 依赖的混合）。

**(b) 首屏空卡片**：`motion.form initial={{ opacity: 0, x: -4 }}` 使 SSR 直出的表单带 `opacity:0` 内联样式，hydration 前用户只看到「标题 + Tab + 底部注册链接」的空卡片（冷启动截图 `shots/light/login.desktop.png` 即为该状态）。建议 `initial={false}` 或改为 CSS 动画，避免 hydration 前的空白态。

# 四、P1 — 明显不协调

### P1-1 · 页头左对齐、内容列居中 → 同页两套对齐轴
`/settings`：PageHeader 文字起点 x≈254，Profile 卡片起点 **x=496**（672px 宽居中），错位 242px。
`/help`：同样的居中列（x=445）vs 左对齐页头。
截图：`shots/light/settings.desktop.png`、`shots/light/help.desktop.png`、`shots/dark/settings.desktop.png`
建议：要么页头跟着内容列一起居中（`max-w-* mx-auto`），要么内容列改为左对齐（`max-w-2xl`，不 `mx-auto`）。

### P1-2 · 同一个 admin 页面出现 3 种 Tab 视觉，且存在重名 Tab
- 一级 Tab（Analytics/Feedback/…）：6 等分 segmented，白底活动胶囊
- Growth 二级 Tab（Customers/FAQ mining/…）：左对齐、**实心紫罗兰**活动态
- Enterprise 二级 Tab（SLA/Routing/…）：左对齐、灰底活动态
- Enterprise 二级最后一项也叫 **"Analytics"**，与一级 Tab 重名

截图：`shots/light/admin-growth.full.png`、`shots/light/admin-enterprise.full.png`、`shots/light/admin-analytics.full.png`
建议：抽出 `<SegmentedTabs>` 单一实现；二级 Tab 改名（如 "企微/客服绩效分析" → `Performance`）。

### P1-3 · 数字与货币格式全站不统一
| 位置 | 输出 | 问题 |
|---|---|---|
| Token 表 Cost | `$12.000000` | `toFixed(6)`（`admin-pages.tsx:647`） |
| Analytics Est. cost | `$412.8700` | `toFixed(4)` |
| Users 表 Token usage tooltip | `$12.48` | `toFixed(4)` 但被换算 |
| platform-admin KPI | `148` / `48213` / `1284123` / `48,213,992` / `4120` | 同一行 4 种格式（只有 tokens 用了 `toLocaleString`） |
| 注册日期 | `2026/9/13`、`2026/9/3` | 月/日不补零 |
| 页面日期 | `2026-08-31` | 与上者又不同 |

建议：统一 `Intl.NumberFormat`；金额固定 2–4 位；日期统一 `YYYY-MM-DD`（或统一 `toLocaleDateString(lang)` 并在同列补零）。

### P1-4 · 语义色对比度不达标（WCAG AA）
用渲染后的前景/背景实算：

| 主题 | 元素 | 字号 | 比值 | 要求 |
|---|---|---|---|---|
| light | `Agent` badge（warning） | 10px | **3.15:1** | 4.5 |
| light | `Waiting` badge（warning） | 10px | **2.84:1** | 4.5 |
| light | `mock` badge（warning） | 14px | **3.15:1** | 4.5 |
| light | `platform_admin` 角色 pill | 11px | **3.15:1** | 4.5 |
| light | `Assigned` badge（info） | 10px | 4.41:1 | 4.5 |
| dark | `Existing doc：`（text-destructive） | 11px | 4.09:1 | 4.5 |

根因：`--app-warning: hsl(36 92% 42%)`（≈#ce7f09）在白底上只有 3.15:1，却被用作 10–14px 正文色；`--app-info: hsl(210 90% 44%)` 处于临界。
建议：warning 前景色压到 `hsl(32 85% 34%)` 级别；badge 文字改用 `text-foreground` + 彩色背景；或至少把 warning 文本字号提到 12px 以上。

### P1-5 · 角色 pill 用「警告色」表示最高权限
`platform_admin` 渲染为琥珀/警告色，`admin` 紫色，`user` 灰色。最高权限被涂成语义上的「注意/警告」，色彩语义反了。建议用 primary/ink 系，而非 warning。

### P1-6 · 暗色下输入框像 disabled，CTA 发灰
`shots/zoom/models-page.dark.png`、`shots/dark/settings.desktop.png`：输入框是平铺的 `--input` 色块（`hsl(228 16% 18%)`）且无描边，文字偏灰；整张表单读起来像全部禁用。暗色下主按钮与非主按钮的分离度也比亮色弱。
建议：暗色 `--app-input` 提高与 `--app-card` 的对比/加 `ring-1 ring-border`；placeholder 单独降一档而不是整体降。

### P1-7 · 字号阶梯失效（设计系统漂移）
globals.css 定义的阶梯：`base 16 / sm 15 / xs 14` —— `sm` 与 `xs` 只差 1px，层级没有意义。实际代码里：
```
token 用法：text-xs ×393、text-sm ×150、text-base ×7
硬编码：   text-[11px] ×126、text-[10px] ×108、text-[13px] ×9、text-[9px] ×7、
           [19px] ×1、[17px] ×1、[15px] ×1、[12px] ×1、[12.5px] ×1
```
DOM 实测同一页并存 **9/10/11/13/14/15/17/20px** 共 8 档。
建议：回归 5 档（11/12/14/16/20），把 `--text-xs` 改回 12px，逐步替换 `text-[10px]/[11px]`。

### P1-8 · 9–10px 文字过多，可读性差
亮色 `/admin#analytics` 一页实测 15 处 <11px：`⌘K`、`Hot` 角标、通知角标 `12`（9px）、kicker、8 个 KPI 标签（10px）、图表刻度（10px）；platform-admin 日期刻度 9px。
建议：正文最小 11px；纯装饰性角标可保留但需保证对比度；图表刻度 ≥11px 并减少刻度数量。

### P2-8 补充根因（这是个 CSS 无效类）
`components/admin/enterprise-tab.tsx:45`
```tsx
<CardHeader className="pb-3 flex-row items-center justify-between">
```
`CardHeader` 基类是 `grid auto-rows-min`。`flex-row` 只设置 `flex-direction`，对 `display:grid` **完全无效**，所以标题与 `action` 图标各占一行 → 图标掉到标题下方。影响 SLA / Routing / Macros / Roles / Webhooks / Performance / Intent / Integrations **全部 8 个 SectionCard**。
修复：把 `flex-row` 换成 `flex`（或直接给容器加 `grid-cols-[1fr_auto]`）。

# 六、其他细节问题

1. **登录页主按钮是白底黑字**（`bg-zinc-50 text-zinc-900`），全站主按钮是紫罗兰渐变；同页的 Google/Telegram 按钮又是 `border-zinc-800 bg-zinc-950` 自成一派 —— 登录页等于自带一套按钮体系，与 `components/ui/button.tsx` 的 6 个 variant 完全不共用。
2. **i18n 缺 key**：`src/app/inbox/page.tsx:396,1289` 调用 `t("inbox.restored")`，但字典里只有 `inbox.restore` → toast 会显示原文 `inbox.restored`。
3. **knowledge 矛盾审查用红色表示「已有文档」**（`Existing doc：` 红、`New doc：` 蓝），红色语义被误用。
4. **Enterprise SLA 输入框无标签**：`300` / `3600` 只有 placeholder，带数字但无单位（秒）。同排第 4 列的按钮是 `h-8`，与输入框同高，但 4 列网格中它没有与任一输入框左边缘对齐。
5. **platforms「凭据状态」大小写不一致**：`verified` / `Receiving` / `Waiting` / `Not verified` 混用。
6. **page-header 的 kicker 用渐变文字 + 10px uppercase + 0.16em 字距**，在深色下渐变端（`hsl(214 95% 72%)` 蓝）与蓝色强调色重复，属于同页第三种蓝色。
7. **notification 角标 9px**，`min-w-4 h-4`，在 28px 触发区上偏小且被 P0-1 的溢出带离原位。
